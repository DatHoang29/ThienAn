# Plan: Migration sang Wolverine local queue + bỏ RawMessage/ProcessedMessage DTO

## Bối cảnh & quyết định
- **Vấn đề bạn thấy**: `Contracts/Messages/` (RawMessage, ProcessedMessage) là boilerplate DTO thừa — pipeline source→queue→worker dùng Channel + DTO riêng, tách rời với MediatR (Activity).
- **Quyết định**:
  1. Wolverine local queue + backpressure (`opts.LocalQueue(...).BufferedInMemory(...)`)
  2. 1 Wolverine handler `ProcessDataCommandHandler` (thay DataWorker)
  3. RawMessage/ProcessedMessage → record (bỏ Contracts/Messages/ folder)
  4. Giữ MediatR cho ActivityNotification + DataPersistedNotification (như bạn nói, 2 cái làm việc khác nhau)
- **Pattern reference**: `Module.CCTV` đã dùng WolverineFx 5.31.0 + `IWolverineHandler`, nhưng ở mode `MediatorOnly` (inline, không queue). Plan này thêm pattern local queue mới (chưa có trong codebase).

## Thiết kế message contract

Bỏ folder `Contracts/Messages/`. Tạo `Features/DataFlow/Messages/` (gần handler, theo feature folder):

```csharp
// Features/DataFlow/Messages/ProcessDataCommand.cs
namespace Services.Sample.Features.DataFlow.Messages;
public sealed record ProcessDataCommand(
    string Source,           // "nats" | "api" | "devices" | "simulation"
    string MessageId,
    DateTime OccurredAtUtc,
    string PayloadJson);
```

`ProcessedMessage` bỏ hoàn toàn — output NATS publish dùng anonymous object hoặc inline trong handler (chỉ DataWorker.cs:91 tạo, không ai consume).

## Thiết kế Wolverine local queue

Trong `AddSampleServices` (hoặc extension riêng `AddWolverineSample`), cấu hình:

```csharp
services.AddWolverine(opts =>
{
    opts.Durability.Mode = DurabilityMode.MediatorOnly;

    // Local queue cho pipeline data — backpressure: block source khi queue đầy.
    // MaximumDepth = QueueOptions.Capacity (default 1000), Restart = 500 (hysteresis).
    opts.LocalQueue("sample-data")
        .BufferedInMemory(new BufferingLimits(maximumDepth: 1000, restart: 500))
        .Sequential(); // single consumer — giữ thứ tự như DataWorker hiện tại (SingleReader channel)

    // Route ProcessDataCommand vào queue sample-data.
    opts.Publish<ProcessDataCommand>().ToLocalQueue("sample-data");
});
```

**Lưu ý Lamar**: `TAC_WebAPI` dùng Lamar DI (`UseLamar()`). `Services.Sample` hiện chạy standalone (Worker/WPF host dùng MS.E.DI default). Cần verify Wolverine hoạt động với MS.E.DI ServiceCollection (Wolverine support cả 2, nhưng phải test). Nếu có vấn đề, dùng `UseWolverineWith()` thay `AddWolverine()`.

## Rủi ro & cách giảm

| Rủi ro | Giảm |
|---|---|
| Wolverine + MS.E.DI (Worker/WPF dùng MS.E.DI, không phải Lamar như TAC_WebAPI) | Wolverine support MS.E.DI. Nếu có vấn đề registration, fallback: Worker/WPF chuyển sang `UseLamar()` (đổi 1 dòng Program.cs). Verify bằng build + runtime test. |
| Handler chạy async qua queue — mất thứ tự strict như SingleReader channel | `.Sequential()` ép single-threaded consumer → giữ thứ tự như cũ. |
| Message lost khi crash (Wolverine in-memory queue không durable) | Giống MessageQueue<RawMessage> hiện tại (Channel cũng in-memory). Nếu cần durable: thêm `.UseDurableInbox()` (scope riêng). |
| Shutdown không drain queue như `queue.TryComplete()` | Wolverine tự drain queue khi host stop (IHostedService). Verify trong runtime test. |
| Backpressure behavior khác Channel (`FullMode.Wait` block caller) | Wolverine backpressure: khi MaximumDepth đạt, listener pause → PublishAsync sẽ block tương tự. Verify trong runtime test với source đẩy nhanh. |
| `MessageQueue.cs` có thể còn dùng chỗ khác | Explore agent sẽ check trước khi xóa. Nếu chỉ Sample dùng → xóa; nếu còn → giữ. |
